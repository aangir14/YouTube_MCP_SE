# C08 Frozen Ranking Evaluation

[Discovery ADR](../adr/ADR-002-discovery-analytics-and-ranking-evaluation.md) · [Versioned seed and judgement manifest](ranking-evaluation-seeds.json) · [QA-RELEVANCE](acceptance-cases.md#qa-relevance) · [C05 ranking evidence](../../brain/resources/ranking-evaluation-metrics.md)

## Public seed set

The v1 manifest takes lectures 1–20 from the [MIT OpenCourseWare 6.006 Spring 2020 lecture catalog](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/lecture-videos/). On 2026-11-25 IST each linked MIT lecture page exposed one distinct YouTube embed ID, which was checked against the manifest. The title and short description fields are author-written labels derived from public lecture topics. They are fixture text. The `source` field links the publisher evidence for each row. The dataset uses public IDs and text only. It contains no account information, video/audio files or transcripts.

All videos double as seeds and retrieval candidates. For each seed, take the other 19 manifest video IDs, sorted ascending by ASCII codepoint. This freezes 380 directed seed–candidate pairs. Both rankers use the same 19 eligible IDs in each query. Evaluate the ranking stage at the post-eligibility seam with a frozen normalized metadata fixture. Production eligibility and provider pagination are separately tested under [ST-FR1](acceptance-cases.md#st-fr1). The source pages establish public publication by the course publisher, and current API availability and eligibility fields can change.

## Relevance judgements

Judge whether the candidate would help a learner extend the seed's central topic at the same course level. Mark `1` for a direct continuation, a specific prerequisite used by the method, a companion example, or an alternative that solves the same class of problem. Mark `0` for broad background or same-course membership alone. A course-review seed uses representative core methods as continuations of the review. Judgements are directed, so an introductory prerequisite can be relevant to an advanced seed even if the reverse order would be less useful. Assign labels from public lecture titles and topic descriptions before inspecting scores or metric results. Each seed's `judgement_basis` explains the positive set and its `relevant_candidate_ids` lists the actual positives. Every other in-pool candidate has an explicit label by complement. Popularity, uploader identity, rank position and similarity scores play no part in judging.

Treat a missing seed annotation or any out-of-pool ID as a validation error. V1 has full in-pool judgement coverage. For a future dataset expansion, require every evaluated pair to be labelled before publishing primary metrics. Track unjudged IDs and coverage separately until reviewed. If revised source evidence requires a new corpus or labels, version it and rerun both methods. Preserve the v1 manifest and its results as a separate comparison.

## Reproduce the paired fixture run

1. Load `ranking-evaluation-seeds.json` and record the version, file SHA-256, and application commit. Check unique 11-character IDs, one source URL per seed, no self-labels, and all relevant candidate IDs within the manifest. Assert every seed has exactly 19 unique candidates and both labels are present.
2. Materialize one offline record per manifest row with its fixed ID, title and description. Project `channel_key` to one shared synthetic channel identity and apply the declared English fixture language. Keep duration, publication date, tags and category unknown as specified. Use the same frozen object set for both arms. Inject a fixed UTC clock (`2026-11-25T00:00:00Z`) and disable live provider/network access. Keep topic annotations and judgements out of the ranker's input. Use this fixture only at the ranking seam so missing duration does not change the selected pool.
3. For each seed, build one shared corpus of the seed and its 19 candidates using the ADR tokenizer, English stop list, raw counts, smoothed IDF and L2 normalization. Rank the full pool first by text cosine alone, then by C08's weighted FR-1 ranker with the SRS default weights `[0.50, 0.15, 0.10, 0.10, 0.10, 0.05]`. Keep score precision, date/ID tie-breaks, normalization and missing-field policy identical. Assert the two ranked ID sets match the pool and that each contains no duplicates. Repeat in fixture mode to check determinism.
4. For each seed and arm, compute precision@5 as the number of relevant results among the first five divided by five. A short list retains denominator five. Compute reciprocal rank as the inverse of the first relevant one-based rank, or zero for no hit. Use the full 19 ranks for reciprocal rank in v1. Macro-average both metrics across all 20 seeds, including zero-hit queries. Save both full ranked lists with labels, scores and per-seed metrics, paired differences and the number of ties. Compute the change as weighted minus baseline. Compare weighted macro precision@5 with the provisional **0.60** target under TBD-4 and report misses.
5. Save the offline reproduction command and fixture revision alongside the results in C26. The product comparison runner and its measured results belong to C26. This contract also calls for synthetic unit fixtures that vary tag, category, duration, language and channel independently of text to prove non-text behavior, missing-field zeroes and trace sums.

For arithmetic verification, a ranked label sequence `0, 1, 0, 1, 0` yields precision@5 = 0.40 and reciprocal rank = 0.50. The sequence `1, 0, 1, 0, 0` has the same precision@5 and reciprocal rank = 1.00. An all-irrelevant ranking yields zero on both measures. Use these checks in [QA-RELEVANCE](acceptance-cases.md#qa-relevance).

## Interpretation and open decisions

V1 is a narrow, single-course judgement set. It measures a reproducible sparse-metadata case, has shared channel and language values, and cannot establish which weights help when metadata is richer. Given the frozen fields, a tie-free v1 text ordering is expected to remain the same after weighting (the remaining nonzero factors are constant). Score rounding can affect narrow ties. Record that outcome honestly and use the synthetic factor checks separately. A richer approved public cohort would need its own frozen facts, labels and documentation before team decisions about general ranking quality.

TBD-8 has a frozen seed and candidate proposal for review. Under TBD-4, revisit feature scales, weights and the 0.60 target only after recording paired evidence and any approved change in the ADR. Keep v1 weights and results available as the baseline. The candidate limits, authorization boundaries and write prohibition come from the SRS and remain in force regardless of evaluation results.
