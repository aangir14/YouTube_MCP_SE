## Request and provider contract

These names describe the tool-specific payloads layered on C07's JSON-RPC and result/error envelopes. Unknown object keys, mismatched types, blank supplied strings, and out-of-range inputs fail before any provider call. Strings and integers are strict. Booleans and numeric strings do not satisfy integer limits. Absent optional keys apply the defaults below.

| Tool | Input object and defaults | Bounded retrieval and return |
| --- | --- | --- |
| `get_video_details` | Required `video_url_or_id: string`. | Read one record by canonical ID. Return the fact sheet, optional public counts, and an untrusted description excerpt of at most 500 characters including any ellipsis. Budget: 0 searches, 1 general unit. |
| `similar_videos` | Required `video_url_or_id: string`; optional strict integer `limit` in 1–50, default 10. | Hydrate the seed first. Use at most 2 search requests including pages plus 1 seed-channel upload page. Use up to 50 entries per page and per hydration batch. Deduplicate, omit the seed and cap at 150 distinct candidates. Budget: 2 searches, 6 general units. |
| `similar_channels` | Required `channel_url_handle_or_id: string`; optional strict integer `limit` in 1–25, default 10. | Resolve the seed and load up to 20 public recent uploads. Use at most 3 channel search requests including pages, 100 distinct non-seed channels and batches of up to 50 IDs. Read recent uploads for no more than the first 10 eligible candidates, ≤20 per channel in one page each. Budget: 3 searches, 25 general units. |
| `recommend_videos` | Required `sources: string[]`, 1–3 distinct values from `likes`, `subscriptions`, `playlists`. Optional trimmed `topic: string`, 1–200 characters when present, and strict integer `limit` in 1–50 (default 10). | Read only selected sources: ≤200 likes (≤4 pages), ≤200 subscriptions (≤4 pages), and ≤5 owned playlists (one list page, ≤100 entries or 2 pages each). Search at most 3 times and read at most one page of up to 50 uploads for each of up to 5 eligible subscribed channels. Candidate ceiling is 400 before hydration (3 × 50 + 5 × 50); earlier quota admission may yield a smaller planned shortlist. Hydrate in batches ≤50. Omit known liked and loaded-playlist IDs from selected authorised sources. Return up to the requested limit from the ranked eligible shortlist. Budget: 3 searches, 40 general units. |
| `analyse_engagement` | Required `sources: string[]` as above. Optional `period` (below) or the scaffold's `period_days` shorthand (30, 90 or 365). Optional `comparison_period` with the same shape and `group_by: "week" \| "month"`, default `week`. | Read the selected sources once, with the same source/page ceilings as recommendations. Reuse the observation set for both periods. Batch and deduplicate hydration IDs, resolve named categories within budget, and report bounded results. Budget: 0 searches, 60 general units. |

Accept case-sensitive bare video IDs matching `[A-Za-z0-9_-]{11}`. Parse HTTPS watch (`/watch?v=ID`), short link (`youtu.be/ID`), Shorts and embed forms on exact supported hosts (`youtube.com`, `www.youtube.com`, `m.youtube.com`, `youtu.be`). Reject userinfo, explicit ports, duplicate `v` keys, non-approved hosts, conflicting video references and other path shapes. A valid watch URL may carry unrelated query context. Emit `https://www.youtube.com/watch?v=ID` for all forms. Channel inputs are canonical IDs (case-sensitive `UC[A-Za-z0-9_-]{22}`), bare `@handle` strings or the corresponding `/channel/ID` and `/@handle` URLs on the approved YouTube hosts. A handle is one nonempty path segment. Keep Unicode; decode once and reject whitespace, controls, or path/query delimiters in the segment. The official provider resolves handle existence. Legacy `/c/` and unsupported URL forms receive a hint to supply a handle or channel ID. Trim inputs and bound URL/identifier input to 2,048 characters as a C08 validation choice. C11 supplies the shared parser.

Malformed identifiers use C07's `INVALID_VIDEO_ID` or `INVALID_CHANNEL_ID`; other malformed arguments use `INVALID_ARGUMENTS`. An inaccessible or missing seed produces `VIDEO_UNAVAILABLE` or `CHANNEL_UNAVAILABLE`. An authorised account without usable recommendation profile evidence returns the SRS `NO_PROFILE_DATA`; absent consent returns `AUTH_REQUIRED` before any provider call. Carry account identity and consent internally in C07's request context. An empty engagement window returns available partial metrics. All tools perform zero writes.

Omitting both `period` and `period_days` defaults to 30 days. Supplying both fails with `INVALID_ARGUMENTS` before provider use. The production account tools require explicit source selection to avoid the scaffold's unspecified account-source behavior.

Send metadata requests only through `VideoProvider`. Normalize candidate intake in declared source order (ordered search requests and pages, then ordered uploads), preserve first occurrence by ID, stop at the candidate limit, then rank independently of provider ordering. For recommendations, choose subscribed channels by descending usable topic/profile text similarity with channel ID ascending for ties; with no usable similarity, choose in channel-ID order. Build search terms from sanitized seed/profile text or the supplied topic with deterministic ordering. At most 3 recommendations queries may use the topic, highest-weight profile terms, or strongest eligible subscriptions. Skip empty or duplicate queries. Reserve the bounded plan before I/O, including required lookups, category reads and allowed retry attempts. The quota gateway rejects unaffordable requests with `QUOTA_BUDGET_EXCEEDED` and zero provider calls. No feature bypasses a cap to fill the display limit. Distinguish genuinely sparse results from truncated reads and expose the reason in warnings.

## Normalized records and eligible items

Use C07's `VideoRecord`, `ChannelRecord` and `AccountActivityRecord` where they preserve provenance. Keep unknown duration, language, dates, keywords, visibility and counts distinguishable from zero, empty values and negative flags. A missing duration represented by the C07 placeholder `0` must carry an unknown marker through C11 rather than become a real zero-second observation. Parse ISO-8601 duration to integer seconds internally. Use UTC timestamps on the wire. Preserve Unicode for display and canonical ASCII IDs for ordering.

For similar-video candidates and recommendations, require confirmed public eligibility, no known live, upcoming or age-restricted state, and a known duration ≥60 seconds. A missing safety-critical eligibility field cannot establish eligibility. Missing tags or language on a video that passes the hard filters affects scoring, not eligibility. The detail tool may return partial facts for a readable seed. A channel is eligible if available and public uploads are evidenced by a positive public-video count or by a readable public upload. Unknown count without evidence stays ineligible until verified within the existing budget.

Use C07's common sanitization boundary and keep external metadata marked untrusted in all returned text, including excerpts, channel display names and text cited in explanations. A final output limit applies after any ellipsis. Public counts are facts for display, except subscriber count in the specified FR-2 size feature. Video views, likes and watch history are excluded as ranking signals.

## Local scoring and tie-breaks

**Shared text transform.** Normalize Unicode NFKC and casefold for scoring only. Tokenize into maximal runs of Unicode letters or numbers (a non-alphanumeric character splits a token). Use the available sanitized title and description as text, and include normalized tags in video text where present. For channel text use title, description and known keywords. For confirmed English documents remove tokens in `a an and are as at be by for from in is of on or that the this to with`; for other or unknown languages skip that list and flag reduced confidence. Preserve repeated terms, give each occurrence equal weight and use no stemming. Use a fixed document set per comparison: seed and eligible candidates for FR-1 or FR-2; distinct usable profile documents and eligible candidates for FR-3. Count a document once per ID, namespaced by type; include empty documents in corpus size. Use raw term count × `(ln((1 + document_count)/(1 + document_frequency)) + 1)` and L2-normalize. Cosine is the dot product of two normalized vectors. An empty vector contributes zero with a missing-text flag. Fit once per pass on the declared corpus. Both evaluation arms use the same corpus and transform.

| Ranker | Named raw features in [0,1] and SRS weights |
| --- | --- |
| Similar videos | **text_cosine** 0.50 above; **tag_overlap** 0.15 Jaccard of normalized, deduplicated whole tags; **category_match** 0.10 exact ID match; **duration_fit** 0.10 smaller known positive duration divided by larger; **language_match** 0.10 equal BCP-47 primary subtags; **same_channel** 0.05 identical canonical channel ID. Known empty tag sets give zero overlap including the empty/empty case. |
| Similar channels | **text_cosine** 0.60; **topic_overlap** 0.20 Jaccard on distinct normalized topic category identifiers; **language_match** 0.10 primary subtag equality, allowing a public-upload evidence mode for a missing native channel language; **size_fit** 0.10 `(1 + ln(1 + min(subscribers))) / (1 + ln(1 + max(subscribers)))` for visible non-negative counts. Hidden counts are unknown even if a default numeric value is present. |
| Recommendations | **profile_similarity** 0.60; **freshness** 0.15 `max(0, 1 - age_days / 365)` using the injected UTC clock and valid publication time no later than that clock; **duration_fit** 0.15 ratio against the median positive profile-video duration; **channel_affinity** 0.10 observed share of deduplicated profile items associated with that channel. *(C17 reconciliation: aligned to SRS FR-3 weights `0.60/0.15/0.15/0.10` instead of the earlier draft `0.60/0.20/0.10/0.10`.)* Compare text to the L2-normalized mean of distinct nonzero source-document vectors. Profile similarity averages text cosine, candidate's frequency share in known profile categories, and frequency share in known primary languages, with one third per term and zero for unavailable terms. Incorporate available subscription channel text, scoped to selected sources. An optional topic shapes retrieval, while the ranker uses the same four profile features. |

For FR-2, pass one uses channel metadata to rank eligible channels. The top ten form a fixed rerank window. In that window, blend the channel text feature with cosine of the two normalized public-upload centroids, equal weight when both signals exist and the sole available signal when only one exists. Fit the upload vocabulary once over the seed and the window's bounded uploads. Use the native channel language when known, otherwise use the most frequent known upload primary language with lexical tie-break, flagging the inference. Recompute weighted scores inside this window and reorder it. Keep the rest in first-pass order. Report the phase because the score is comparable within its phase. If no uploads can be used within the admitted budget, retain first-pass evidence and disclose the limit.

For a missing side of a feature, use raw zero, flag the actual missing field(s) and do not renormalize weights. Known mismatches also score zero but carry no missing flag. Use fixed feature names and finite weights summing to one. Sort by descending score rounded to six decimals (half-even), then for video results newest known publication first, unknown date last, then item ID ascending by ASCII codepoint. Channels use the same rounded score and ascending channel ID within each phase. Assign one-based rank after sorting. Use stable codepoint ordering on ties in category frequencies, reason terms and contributors. Keep full internal precision for scoring and round display scores after weighting. Return the chosen normalized score in [0,1].

**Trace and output.** Retain C07 ranked fields `item_id`, `title`, `score`, `rank`, `reason`, `components`, `shared_terms`, `missing_fields`, `low_confidence`. Add normalized public metadata (including `canonical_url`, public channel and video duration where applicable) and a tool-specific `feature_trace` keyed by factor name with numeric `raw`, `weight` and `contribution`. Keep C07's flat `components` shape for compatibility and give it the named effective weights. Contributions are raw × weight, serialized with enough precision to sum to the returned score within 0.000001. For subfeatures such as upload text or profile category evidence, include audit evidence without double-counting contributions. Select up to five shared terms ranked by pairwise TF-IDF product descending, then lexical term. Generate reason text locally from highest positive contributions (weight contribution descending, then factor name), at most 200 characters. Explain sparse results and mark a result low confidence if text or language is missing or if non-English/unknown-language fallback preprocessing was used. For recommendations include up to three contributing profile video/channel references by descending positive document cosine and then ID, restricted to the authorised result, and disclose that watch history is unavailable. Expose the active named defaults at `focuslist://config/scoring` in C26. Explanations make zero provider calls.

## Engagement periods, counting and provenance

- **Periods.** A period is either `{"days": 30}`, `{"days": 90}`, `{"days": 365}` or `{"start": "...", "end": "..."}`. Accept calendar dates `YYYY-MM-DD` as UTC midnight or RFC 3339 timestamps with an explicit offset, normalize to UTC and require start < end. Each window is start inclusive, end exclusive. Capture the injected UTC clock once for presets, with `end = now` and `start = now - days × 24h`. To compare with the preceding window, pass its explicit bounds. Evaluate overlapping windows independently if supplied. Weeks start Monday 00:00 UTC and months start on day 1 00:00 UTC. Return occupied buckets with boundaries clamped to the window. Gaps represent zero observations, so a long explicit period need not allocate empty rows.
- **Observation identity.** Count each canonical liked video once per likes source, each subscribed channel once per subscriptions source and each distinct playlist-item membership once within its playlist. Deduplicate repeated API pages by source-native ID; use playlist/item identity so a video in two playlists contributes two memberships. Reuse the same hydrated video across all memberships. A video seen as a like and a playlist item contributes to both sources; call totals observations, not unique videos. Subscription rows count toward channels and source totals, with no invented video category or duration. This design needs a source/playlist-item identity alongside C07's `item_id` before C23 can deduplicate.
- **Dates.** Bucket genuine playlist-add, documented subscription-creation and verified like-event dates when available; preserve the event field separately. For a video-backed row lacking a usable event date, fall back to its valid publication time and mark `publication_fallback`. For a subscription without usable creation time, or video row without either date, exclude it from period metrics and count it in `undated_by_source` separately. No fetch-time stand-in. Return per-bucket source/basis counts (`genuine` vs `publication_fallback`), and say “Some trend points use the video's publication date. The actual like or playlist add date was unavailable.” An undated warning names the omission. Mixed-basis comparisons carry the fallback warning even if the aggregate is computable. [C05 timestamp evidence](../../brain/resources/account-activity-timestamp-provenance.md)
- **Metrics.** In each period, return `window`, `observation_count`, `source_counts`, `top_channels`, `top_categories`, `duration`, and `trends`. Sort channel/category rows by count descending then canonical ID ascending. Channel shares divide by observations with a resolved channel; category shares divide by observations with a resolved category name. Include counts, denominator and unknown counts, and use null for a share when its denominator is zero. Use category IDs for grouping, names for display. Leave unresolved names out of the named ranking and report them as unknown. Duration mean and median use known video durations only, in seconds (null when empty). Histogram bins in seconds are `[0,300)`, `[300,600)`, `[600,1200)`, `[1200,2400)`, `[2400,3600)`, and `[3600,+∞)`. Return known/unknown duration counts. Charts use the same results.
- **Comparison.** Pair stable numeric metric keys by channel ID, category ID, source name or histogram bin. For counts missing from a nonempty baseline use zero for the missing key. Return current, baseline, absolute delta `current - baseline` and percentage delta `100 × delta / baseline` when operands exist and baseline is nonzero and nonempty. Use null percentage for zero/empty baseline and null deltas for unavailable operands. Shares are fractions and their absolute delta is in fraction units. A period with fewer than ten observations gets a partial-data warning, including an empty period. Return a short local summary naming partial, fallback or truncated evidence without inventing an activity inference.
